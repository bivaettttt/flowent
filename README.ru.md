# Flowent

[Русский](README.ru.md) · [English](README.en.md)

Flowent — учебная платформа согласований. Аналитик редактирует BPMN 2.0 XML, валидирует модель и публикует неизменяемую версию. Движок исполняет эту версию и сохраняет задачи, маршрут токенов, таймеры и инциденты в PostgreSQL. Исторические экземпляры продолжают работу по исходной версии.

## Запуск

```sh
docker compose up --build --wait
```

Откройте [рабочее пространство](http://127.0.0.1:8120). Учебная среда публикуется на loopback. Compose применяет миграции и идемпотентно создаёт синтетические данные. Настройки `FLOWENT_PORT` и `FLOWENT_DEMO_PASSWORD` переопределяют локальный порт и пароль начального наполнения. Для всех предустановленных аккаунтов начальный пароль по умолчанию `Flowent-demo-local`.

| Логин | Рабочий сценарий |
| --- | --- |
| `employee` | Запустить экземпляр и отслеживать собственные заявки |
| `analyst` | Открыть BPMN-редактор, проверить и опубликовать модель |
| `manager` | Выполнить проверку менеджера |
| `approver`, `finance`, `security`, `it` | Выполнить задачи соответствующих групп |
| `admin` | Просмотреть инциденты, отчёты, пользователей и Lab |

Изолированная лаборатория использует отдельный проект Compose и том PostgreSQL.

```sh
scripts/lab up
```

Откройте [Flowent Lab](http://127.0.0.1:8121) под `admin`. `scripts/lab stop` останавливает среду, `scripts/lab reset` удаляет её учебные данные и пересоздаёт её.

## Что можно проверить

- Расходы. Условный шлюз выбирает маршрут по сумме.
- ИТ-доступ. Проверки безопасности и ИТ идут параллельно. Задача после соединения появляется после обеих проверок.
- Командировка. Менеджер может вернуть заявку, после исправления она проходит повторное согласование.
- Lab показывает реальные HTTP-ответы, состояние экземпляра и последовательность событий до и после проверяемых действий.

Пошаговый маршрут, скриншоты и запись доступны в [демонстрации](docs/demo.md).

## Архитектура и API

React и bpmn-js работают с FastAPI через nginx. PostgreSQL хранит определения, версии, экземпляры, токены, задачи, квитанции команд и журнал событий. Отдельный worker выбирает созревшие задания из PostgreSQL и выполняет таймеры, SLA и сервисные задачи. Токен сессии хранится в памяти браузера до перезагрузки страницы.

Движок поддерживает None Start/End, User Task, Service Task, Exclusive Gateway, структурированный Parallel Gateway и промежуточное Timer Catch Event. Условия и типы полей определяются в BPMN XML. Допустимые действия сервисных задач заданы в коде.

- [Модель, правила и права](docs/model.md)
- [Семантика BPMN и решения](docs/architecture.md)
- [OpenAPI](docs/openapi.json)
- [Тесты и трассируемость](docs/verification.md)
- [Ограничения и статус](docs/PROJECT_STATUS.md)

`backend/` содержит API, миграции и движок, `frontend/` — интерфейс и браузерные тесты, `scripts/` — команды локальной проверки, `docs/` — BPMN, контракты и анализ, `assets/` — материалы реального запуска.

## Рабочий цикл и безопасность

В редакторе измените граф или свойства элемента. Проверка отделяет целостность XML от исполняемой семантики. Менеджер публикует сохранённый черновик. Исполнитель берёт доступную задачу и отправляет форму, закреплённую за опубликованной версией. Монитор показывает текущие токены, завершённые шаги и сервисные сбои. При исчерпании попыток администратор повторно ставит задание в очередь с указанием причины.

Стек включает Python, FastAPI, SQLAlchemy, Alembic, PostgreSQL, TypeScript, React, Vite, bpmn-js, Docker Compose и Playwright. Интерактивный контракт доступен по [локальному Swagger UI](http://127.0.0.1:8120/api/docs). Ограничения и варианты развития зафиксированы в [статусе проекта](docs/PROJECT_STATUS.md). Авторские исходники опубликованы без отдельной лицензии. Компоненты третьих сторон сохраняют условия своих лицензий. [Проверки GitHub Actions](https://github.com/bivaettttt/flowent/actions).
