## Дизайн-система

- Левый тёмный rail отделяет моделирование, исполнение и управление. На узком экране те же разделы доступны через кнопку с `aria-expanded`. Светлые поверхности и границы выстраивают приоритет формы, схемы и истории. IBM Plex Sans поддерживает кириллицу и табличные данные. Идентификаторы выделены моноширинным шрифтом и переносятся внутри доступной ширины.
- В моделировании главное действие зависит от состояния черновика и роли. Компактные команды управления схемой отделены от сохранения и публикации. Инспектор показывает BPMN ID, тип и настройки исполнения. Управление XML и конфигурацией доступно отдельно.
- Монитор показывает опубликованную модель, этап ожидания и контекст исполнения перед подробной хронологией. Маркеры состояния продублированы текстом. Поиск, сортировка и страницы основных реестров используют URL. Выбор BPMN-элемента доступен с клавиатуры. `prefers-reduced-motion` отключает декоративные переходы.

## Модель исполнения

Монитор получает XML опубликованной версии по `instance.version` через доступ к самому экземпляру. Публикация новых версий не меняет существующие связи. UUID версии и номер показаны отдельно. Для управленческих ролей переход из опубликованной версии открывает экземпляры именно этой версии.

Для JOIN клиент использует записанную движком активацию `FORKED` и идентификатор кадра из стека токенов. Ожидание одной активации отделено от других. Если фактических данных недостаточно, интерфейс сообщает это. BPMN-таймер показывает параметры модели, план `due_at` и событие срабатывания. Сроки экземпляра и задач показаны отдельно, время подписано UTC. Остаток времени вычисляется по серверным часам стенда и учитывает лабораторный сдвиг.

Постановка сервисной задачи в очередь отображается отдельно от завершённого восстановления. История связывает новый `SERVICE_DONE` с конкретным `job`. Для старых событий, записанных до добавления идентификатора, интерфейс может показать статус задания без точной даты подтверждения. Движок и миграции существующей схемы сохранены, история дополняется метаданными.

## Ограничения

- На телефоне визуальное редактирование канвы выключено. Схема поддерживает инспекцию, текстовый выбор шага, масштаб и команды возврата к полному виду. Пространственное редактирование всем набором инструментов bpmn-js не покрыто клавиатурой.
- Название элемента можно изменить в инспекторе. Исполняемые формы, маршрутизация, присвоения и таймеры редактируются в существующем режиме XML. Новые типы процессов и условия выполнения выходят за границы поддерживаемого BPMN-подмножества.
- Результаты Chromium описывают конкретные проверенные маршруты. Полное соответствие WCAG требует отдельной проверки скринридеров, увеличения и независимого браузерного движка.

## Приёмка аудита

Сценарии Chromium используют отдельные демонстрационные БД. В матрице «частично» означает, что существенный путь проверен, а часть комбинаций или средств ввода остаётся за пределами прогона.

| Критерий | Статус | Проверка и границы |
| --- | --- | --- |
| AC-01 · Геометрия редактора | Проверено | Тест вычисляет зазоры между геометрией BPMN, палитрой и границами canvas. На 1440 и 1600 px порог 12 px. |
| AC-02 · Свойства элемента | Частично | Выбор `Solo` из списка и через canvas, изменение имени и ID. Настройки группы, полей и срока извлекаются из BPMN. Для всех видов фигур на 768 px нет отдельного теста. |
| AC-03 · Актуальность проверки | Проверено | Изменение ID отменяет успех. API отклоняет несовпадающий SHA-256, устаревшую редакцию и синтаксически или семантически недопустимую модель. |
| AC-04 · Диагностика | Частично | Ошибка неподдерживаемой фигуры проверена через API. Для отсутствующего `Solo` Enter переводит фокус к исходнику. Полная браузерная матрица диагностик XSD и таймеров не пройдена. |
| AC-05 · XML и черновик | Частично | Реальный Export → Import → Save → Validate → Publish → Execute и защита Back/выхода. Автоматический структурный diff координат для произвольного перемещения не добавлен. |
| AC-06 · Публикация и история | Проверено | HTTP проверяет роли и редакции. Исторический URL показывает исходный XML. PostgreSQL запрещает изменение опубликованной записи. |
| AC-07 · Список экземпляров | Проверено | HTTP 200 для нескольких разрешённых выборок и 404 для чужого экземпляра. В браузере запуск создаёт запись и открывает монитор. |
| AC-08 · Закреплённый BPMN | Проверено | Реальные экземпляры используют старую и новую версии соответственно. Из монитора открывается точный XML, из просмотра версии доступна отфильтрованная выборка. |
| AC-09 · Параллельные задачи | Проверено | HTTP и браузер видят реальные `Lead` и `Second`. Название, роль, срок, статус и ID берутся из записи задачи. |
| AC-10 · Выполнение задачи | Частично | Claim, форма, завершение, повтор с тем же ключом и конфликт с новым ключом. Сценарий потери ответа с последующим повтором из двух открытых вкладок не выполнялся. |
| AC-11 · Split | Проверено | Последовательный и конкурентный HTTP-проходы, ровно один `JOINED`. |
| AC-12 · Ожидание JOIN | Частично | Chromium сверяет одну из двух ветвей и переход к завершённой синхронизации. Вложенные параллельные активации отдельно в браузере не запускались. |
| AC-13 · Таймер | Проверено | Живой Timer Catch, `due_at`, `TIMER_FIRED` и сохранность при перезапуске. |
| AC-14 · SLA и зона | Частично | Лабораторная просрочка, отдельные сроки задачи и экземпляра, UTC. Агрегаты отчёта не пересчитывались независимо по SQL для всех состояний. |
| AC-15 · Инцидент | Частично | Блокировка и две предшествующие попытки, код, узел, версия и история. Ограничение retry защищено ролью ADMIN, отдельный визуальный проход менеджера не записан. |
| AC-16 · Восстановление | Частично | Остановка worker подтверждает QUEUED без подтверждения, запуск worker подтверждает RECOVERED. Возврат в повторный отказ при сохраняющемся сбое не пройден отдельным браузерным сценарием. |
| AC-17 · Хронология | Частично | Событие ведёт к BPMN-узлу, полный Request ID и Actor ID доступны внутри детали. Имена ролей для отдельных исторических действий не денормализованы. |
| AC-18 · Reflow | Проверено для Chromium | Список шагов, режим просмотра и отсутствие горизонтальной прокрутки документа для проверенных экранов на 1440, 768, 390 и 320 CSS px. |
| AC-19 · Клавиатура | Частично | Диагностика, Tab/Enter, Escape, выбор шага, возврат по навигации проверены в Chromium. Пространственное редактирование и второй браузерный движок не входили в прогон. |
| AC-20 · WCAG 2.2 AA | Частично | Семантика, видимый фокус, доступные имена, узкий viewport и reduced motion. Полной ручной проверки VoiceOver, 200% zoom и всех состояний не проводилось. |
| AC-21 · Регрессии | Проверено | Unit, HTTP и PostgreSQL, сохранность при перезапуске, Lab, сборка и Chromium. Стабильный XML монитора сохраняет экземпляр Viewer при изменении маркеров. |
| AC-22 · Lab | Проверено | 14 реальных сценариев, серверный ACL, запросы и сверяемые технические результаты. |
| AC-23 · Контекст ссылок | Частично | Фильтр реестра сохраняется в URL, переходы монитор → версия и журнал → экземпляр. Полная матрица ролей, Forward и повторного входа для каждого маршрута не прогнана. |
| AC-24 · Состояния интерфейса | Частично | Воспроизведены загрузка, валидация, ревизионный конфликт и пустая выборка. HTTP 500 воспроизводился в исходном состоянии, в финальном браузерном проходе искусственно не внедрялся. |
